# `rustleaks-sources` fuzz targets

This page is for contributors. This folder is a standalone `cargo-fuzz`
package for the source adapters. It turns on the production `archives`
feature without changing the root workspace or its lockfile.

## Targets

| Target | What it covers | Input limit | Seeds |
| --- | --- | --- | --- |
| `archive` | Archive formats, traversal, links, expansion, entry counts, nesting and callback control | 8 KiB | Generated by `generate archive-fuzz-seeds`, plus `seeds/archive/` |
| `reader_schedule` | Chunking, short reads, read errors, cancellation, stop and callback errors | 4 KiB | `seeds/reader_schedule/`, plus generated framed seeds |
| `git_patch` | Patch parsing, quoting, renames, copies, binary changes, submodules, hunk counts and line endings | 16 KiB | `seeds/git_patch/`, plus generated framed seeds |

Each target has a dictionary in `dictionaries/<target>.dict`. Shared harness
code is in `support/`. The deep profile allows 64 KiB inputs, archive depth
4, 256 entries, 1 MiB per member, 4 MiB of total output and 4 KiB file
chunks. It does not raise the per-operation reader and Git limits.

## `archive`

An archive input starts with the four bytes `RLA\x01`. One format selector
byte and one callback control byte follow, then the archive bytes. Control
bit 0 cancels before the entry, bit 1 cancels after an event, and bit 2
stops after an event. Short headers and unknown versions do not reach the
source.

The 8 KiB limit includes the six-byte header. Traversal allows two archive
levels, eight entries, 128 KiB per member, 128 KiB of total decoded bytes and
an 8 KiB spool. Files are read in 512-byte chunks with 128 bytes of
read-ahead. Decoder memory limits also use the member limit. This leaves room
for the smallest LZIP dictionary and the 128 KiB windows of the RAR3 and RAR5
seeds. Production archive defaults do not change.

Archives stream from their input, so each input is scanned twice: once from
memory and once in reads of one to seven bytes. Both runs must give the same
fragments, issue stages and kinds, and result. Inputs that cancel after an
event are scanned once, because the next cancellation poll can come at a
different point.

`just fuzz-smoke` builds the archive corpus from shared synthetic seed
builders and reviewed fixtures. The generator writes a `corpus/` folder, a
manifest with hashes and origins, and the license files. The corpus has 90
inputs. It covers all sixteen format selectors, RAR2, RAR3 and RAR5, and
Snappy and S2 framing. The 7z seeds cover COPY, Deflate and LZ4 with plain
headers. Other 7z methods, encoded headers and larger coder graphs are not
covered.

To build and check the corpus on its own:

```sh
bazelisk run //crates/xtask:xtask -- generate archive-fuzz-seeds /tmp/rustleaks-archive-seeds-v1
bazelisk run //crates/xtask:xtask -- generate archive-fuzz-seeds /tmp/rustleaks-archive-seeds-v1 --check
```

This command accepts any absolute output path, including one under `/tmp`
on macOS, where `/tmp` is a symbolic link.

Notes on the seeds:

- The two files in `seeds/archive/` keep their original bytes without a
  header. The generator frames them with `archive_frame::migrate_legacy`,
  which uses their first byte as both the format selector and the control
  byte. The target does not run an input without the header.
- `support/sevenz_seeds.rs` builds the two compressed 7z seeds. Each holds one
  `value.txt` member with `CODEC_PAYLOAD` repeated eight times. Deflate uses
  `miniz_oxide 0.9.1` raw compression at level 6. LZ4 uses `lz4_flex 0.14.0`
  with the default frame encoder.
- The XZ seed holds the shared two-member USTAR fixture, compressed with
  Python `lzma` (`FORMAT_XZ`, `CHECK_CRC32`, LZMA2, 4 KiB dictionary). The
  LZIP seed holds the shared codec payload in raw LZMA1 (4 KiB dictionary,
  `lc=3`, `lp=0`, `pb=2`). The corpus uses these fixed bytes and needs no
  external compressor.

`tests/archive_fuzz.rs` uses the same frame decoder and harness as the
target. It checks every selector and control combination, decoded payloads
for every seeded format, the framing of the unframed seeds and the member
limit.

The target supports only `panic=unwind`. A compile-time check rejects
`panic=abort`. Known 7z and RAR decoder panics become source issues only in
unwind builds. Any other panic is passed on, so libFuzzer records the input as
a failure.

## `reader_schedule`

The target drives the reader protocol with schedules of zero progress, short
reads, data with end of file, data with an error, too-large counts,
cancellation, stop and callback errors. Each read returns at most 15 bytes.

A framed input starts with `RLR\x01`. One byte each follows for chunk size
minus one, read-ahead, callback stop, callback error, cancellation before the
scan and cancellation in the callback. A little-endian `u16` schedule length
comes next, then the schedule and the payload. Flags use bit 0. Chunk size is
1 to 64 and read-ahead is 0 to 63. The 12-byte header counts toward the
input limit. The target also accepts unframed inputs, where one byte (two in
the deep profile) selects the schedule.

## `git_patch`

The target runs the in-process Git patch parser. It does not start Git. A
framed input starts with `RLG\x01`, then one byte each for the file limit
minus one, the hunk limit minus one and cancellation, then the patch bytes.
The file limit is 1 to 32, the hunk limit is 1 to 256, and cancellation uses
bit 0. The seven-byte header counts toward the input limit. Parser lines are
limited to 2,048, and metadata and paths to 4 KiB each. The target also
accepts unframed inputs, which start with one control byte. Parsing the same input twice
must give the same result.

`source_fuzz_test` checks the generated reader and Git seeds: emitted bytes,
parser counts, separate controls, limits and the unframed formats.

## Running

Run these commands from the repository root. Archive and framed seeds are
generated automatically:

```sh
just fuzz-build
just fuzz-smoke
just fuzz run --output /private/tmp/rustleaks-source-fuzz-run
```

The output folder must be new and outside the checkout. Treat crash inputs
and diagnostics as sensitive. Do not run an unreviewed pull request corpus
through a trusted cache. Direct `cargo fuzz` commands print raw crash bytes
and do not keep the private output rules. See the [private fuzz
workflow](../../../docs/dev/security-checks.md#private-local-fuzz-evidence)
for replay, minimizing and corpus promotion, and the [larger structured
tests](../../../docs/dev/security-checks.md#larger-structured-tests) for
inputs above these limits.
