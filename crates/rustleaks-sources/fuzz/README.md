# `rustleaks-sources` fuzz targets

The limits below describe smoke and extended campaigns. The optional deep
profile admits 64 KiB inputs, archive depth 4, 256 entries, 1 MiB per member,
4 MiB aggregate output and 4 KiB file chunks. Versioned reader and Git frames
give each sizing, callback and cancellation control a separate field. Legacy
inputs retain their original mappings, including the old control correlations.
Deep increases reader/Git input length without increasing their per-operation
limits. Larger inputs do not establish per-codec source
coverage. Separate structured cases exercise archive limits and count actual
reader operations; see the [structured-case contract](../../../docs/SECURITY_STRESS.md).

This standalone package enables the production `archives` feature without
changing the root workspace or lockfile.

## `archive`

Archive inputs use frame version 1: the four bytes `RLA\x01`, one format
selector byte, one callback-control byte, then the archive payload. The format
selector and control byte are independent. Control bit 0 requests cancellation
before entry, bit 1 cancels after an event, and bit 2 stops after an event.
Unknown versions and short headers do not enter the source.

The 8 KiB input limit includes the six-byte frame. Traversal is limited to two
archive layers, eight entries, 128 KiB per member, 128 KiB total decoded bytes,
and an 8 KiB spool. File fragments use 512-byte chunks with 128 bytes of
boundary read-ahead. Decoder memory limits also use the member cap. The pinned
LZIP decoder needs 42 KiB for its smallest 4 KiB dictionary, including
probability and speculative-decoding state. The reviewed compressed RAR3/RAR5
seeds declare 128 KiB windows. The cap admits these decoding paths without
increasing the aggregate output budget. Production archive defaults are unchanged.
Event accounting permits short decoder reads and bounds nonempty events by
emitted bytes, with an additional terminal-issue allowance per entry.

`just fuzz-smoke` generates its archive corpus from the shared synthetic seed
builders and reviewed source corpus/fixtures. The generator writes a separate
`corpus/` directory, a manifest with frame/content hashes and origins, and
retained licenses. It includes successful inputs for all sixteen format
selectors, RAR2/RAR3/RAR5 paths and Snappy/S2 framing. TAR and compressed TAR
include two members. The 7z seeds cover COPY, single-coder Deflate and LZ4
with plain headers. Other methods, encoded headers and more complex coder graphs
need separate evidence.

The two files in `seeds/archive/` retain their original unframed bytes as
migration inputs. The generator preserves the old first byte as both the
format selector and callback control, and preserves the remaining payload.
New valid seeds use independent fields. Old crash artifacts must be explicitly
migrated before replay; they must not be passed directly to the v1 target.
Migration rejects inputs that cannot fit without truncation after framing.

Generate and check a standalone corpus from the repository root:

```sh
bazelisk run //crates/xtask:xtask -- generate archive-fuzz-seeds /tmp/rustleaks-archive-seeds-v1
bazelisk run //crates/xtask:xtask -- generate archive-fuzz-seeds /tmp/rustleaks-archive-seeds-v1 --check
```

`tests/archive_fuzz.rs` uses the same frame decoder and exercise function as
the fuzz target. It checks every selector/control combination, complete decoded
payloads for every seeded format, callback modes, framing, legacy migration,
and the member-byte limit. Re-coupling the selector and callback bits fails
these ordinary Bazel tests. Seed generation has an idempotent check and rejects
unexpected files in its output tree.

The two compressed 7z seed constants are generated by the maintained
`fuzz/support/sevenz_seeds.rs` test helper. Each contains one `value.txt` member
with the 28-byte `CODEC_PAYLOAD` repeated eight times. Deflate uses
`miniz_oxide 0.9.1` raw compression at level 6; LZ4 uses `lz4_flex 0.14.0` with
the default frame encoder. The helper builds the plain 7z header and output CRC.
Ordinary tests regenerate the exact archive bytes, prove actual compression,
and compare all decoded content. The generator records both seed and helper
identities without adding encoder dependencies to xtask. Each seed receives
normal, pre-cancel, callback-cancel and stop frames, bringing the corpus to
90 inputs. Separate archive semantic tests cover finite payload, order, CRC,
truncation, resource, nesting and cancellation cases for these three methods.

The synthetic XZ constant encodes the shared two-member USTAR fixture with
Python `lzma.compress`, `FORMAT_XZ`, `CHECK_CRC32`, and an LZMA2 filter with a
4 KiB dictionary. The synthetic LZIP constant contains the shared codec
payload encoded with `FORMAT_RAW`, LZMA1, a 4 KiB dictionary, `lc=3`, `lp=0`,
and `pb=2`; its version-1 header uses dictionary code 12 and its trailer stores
CRC32, uncompressed size, and member size. The ordinary tests compare the
complete decoded content with the independent expected bytes. Corpus generation
uses these reviewed constants and requires no external compressor.

This target is intentionally supported only with `panic=unwind`. The 7z/RAR
dependency guards can convert known dependency panics into recoverable issues
only under unwind builds. A compile-time guard rejects `panic=abort`, and an
outer `catch_unwind` immediately resumes any panic not contained by production
code so libFuzzer records the input as a failure. No claim is made that archive
decoding is panic-contained in a downstream `panic=abort` binary.

## `reader_schedule`

This target drives the public compatibility reader protocol with bounded
zero-progress, short, data-plus-EOF, data-plus-error, overreported-count,
cancellation, stop, and callback-error schedules. Each operation produces at
most 15 bytes and the schedule is capped by the 4 KiB fuzz input.

A complete v1 frame starts with `RLR\x01`, then one byte each for chunk size
minus one, boundary read-ahead, callback stop, callback error, pre-cancellation
and callback cancellation. A little-endian u16 schedule length follows, then
schedule and payload bytes. Boolean fields use bit zero. Chunk size is 1..64
and read-ahead is 0..63. The schedule length clamps to the remaining input.
The 12-byte header counts toward the smoke 4 KiB or deep 64 KiB input limit.

All other inputs, including short headers and unknown versions, use the legacy
format. Its smoke schedule selector is one byte; deep uses two bytes. Complete
v1 prefixes reserve part of the former arbitrary-input space. Existing committed
and generated deep seeds have no prefix collisions and retain their old
interpretation; arbitrary older artifacts need review before reuse.

## `git_patch`

This target drives the production in-process Git patch parser without spawning
Git. A complete v1 frame starts with `RLG\x01`, then separate bytes for file
ceiling minus one, hunk ceiling minus one and pre-cancellation, followed by
patch data. The file ceiling is 1..32, the hunk ceiling is 1..256 and cancellation
uses bit zero. The seven-byte header counts toward the 16 KiB smoke or 64 KiB
deep input limit. Parser lines remain capped at 2,048; metadata and path bytes
are capped at 4 KiB each. Other inputs retain the legacy leading control byte
and its coupled limits/cancellation behavior.

Patch bytes include invalid
UTF-8, quoting, metadata, renames, copies, binary markers, submodules, hunk
counts, and line endings. Repeated parsing must return the same classification
and bounded file/hunk summary.

The maintained runner adds eight synthetic framed reader seeds and four framed
Git seeds to both smoke and deep corpora, alongside the existing seeds. They
exercise successful consumption/parsing and separate control failures. Ordinary
`source_fuzz_test` checks actual emitted bytes, parser counts, control
independence, bounds, legacy mappings and the 129-hunk path that formerly
implied pre-cancellation. These examples do not establish arbitrary chunk
equivalence or classify the Git hook's internal rejection errors.

Run the maintained private campaigns from the repository root. Archive and
framed source seeds are generated automatically:

```sh
just fuzz-smoke
just fuzz run --output /private/tmp/rustleaks-source-fuzz-run
```

The output path must be new and outside the checkout; this example uses
macOS's non-symlink temporary directory. Failed runs preserve private artifacts,
logs and exact invocation provenance. Explicit-output successful runs retain
corpus progress for bounded coverage merging and reviewed local promotion.
See the [private fuzz workflow](../../../docs/SECURITY_CONTROLS.md#private-local-fuzz-evidence)
for replay, artifact reproduction, crash minimization and corpus review.
Do not run unreviewed PR corpora through a shared trusted cache or publish raw
crash artifacts. Direct cargo-fuzz output can disclose crashing bytes.

These are bounded panic/hang/resource-pathology campaigns, not native
Linux/Windows runtime evidence and not universal OOM guarantees.
