# Semantic assertion corpus

This directory is the deterministic machine-readable semantic assertion layer
beneath the executable `TM-*` and `BM-*` inventory. It does not add Go test
processes or change the global manifest totals.

## Files and exact totals

- `assertions.jsonl`: exactly 283 semantic rows (92 base-config loop leaves,
  168 regex-generator leaves, and 23 direct/inline rows).
- `benchmark-links.jsonl`: exactly six benchmark correctness-link records.
- `platform-skips.jsonl`: exactly two explicit Windows skip annotations.

Every JSONL object is schema version 1 and retains the pinned revision, source
file and line, stable source occurrence, existing manifest parent, observation
lane (`public-api`, public integration, or oracle adapter), exact expectation
kind, fixture links, and explicit Rust test/evidence disposition fields.
Repeated input bytes
remain separate rows when they are separate source occurrences. Generator rows
retain the true/false case-insensitive cross-product in both their identity and
`source_occurrence`.

## Byte representation

All source/expected string values inside `input` and `expected`, including
empty strings, paths, diagnostics, newlines, tabs, CRLF, golden IDs, and
finding fields, use:

```json
{"encoding":"base64","data":"..."}
```

Decode `data` with strict RFC 4648 base64 and do not apply Unicode, newline,
path-separator, case, or dot-component normalization. Numeric and boolean
values remain native JSON values. Arrays and objects preserve semantic shape;
where upstream explicitly ignores order, the expectation kind names that
exception (`unordered-exact-set` or `no-error-normalized-sets`).

## Provenance and verification

The source is Gitleaks under its MIT license, pinned at
`b58d3f102cf3a2c84cb7f923d05c25c9b1aed84b`. The corpus is derived evidence,
not an independent upstream fixture copy. Fixture payload provenance remains in
`compat/test-manifest.toml`; corpus rows refer to its `FIX-*` identities.

From the Rust repository root:

```sh
ruby compat/extract_assertions.rb --check
```

The checker verifies the sibling upstream checkout revision, exact SHA-256 of
all nine contributing Go source files, exact row counts and unique identities,
every `TM-*`, `BM-*`, and `FIX-*` reference in the current manifest, and the
complete byte-for-byte regenerated JSONL content. The final corpus contains
115 implemented rows with named Rust tests and 168 precise final dispositions
for Go-only configuration-generator helpers. The six benchmark links and both
upstream Windows skip branches also name final Rust evidence. No pending row is
accepted. An optional directory makes
negative-control checks possible without editing this corpus:

```sh
ruby compat/extract_assertions.rb --check /path/to/copied-corpus
```

A same-count identity or payload substitution fails because the checker
compares canonical regenerated bytes rather than accepting totals alone. Use
`--write` only when intentionally regenerating from the locked extractor.

## Deliberate boundaries

- `BM-0003` and `BM-0004` are workload replays of the 24 path and 68 regex
  assertions; they do not create additional benchmark correctness records.
- The JUnit rows use only upstream's `lineEndingReplacer` normalization and
  otherwise require exact golden content.
- Staged-Git execution must use an isolated fixture copy because upstream
  renames `dotGit`; symlink execution requires a native non-Windows symlink.
- Baseline injection/state, location internals, and normalized ignore-set state
  remain explicit adapter lanes with named executable Rust evidence.
