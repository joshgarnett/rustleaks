# GNU corresponding source and relinking

The `rustleaks-VERSION-corresponding-source.tar.gz` release asset supplies the
application source and the glibc source and build inputs used by the two GNU
Linux executables. The signed native archive's `licenses/index.json` records
the companion asset's SHA-256 digest in `corresponding_source`. Verify the
native archive's GitHub attestation and that digest before extracting the
companion asset. The release also retains native source-relink evidence for
each GNU target.

## Contents and provenance

`application.tar` is `git archive --format=tar` of the exact release candidate.
It includes the CLI, source adapters, workspace source, licenses, Cargo and
Bazel locks, and build definitions, preserving Git file modes and symlinks.
The published core crate alone does not contain this application source.

`inputs/` contains the unchanged, checksummed upstream archives below. Their
original license files, copyright notices, file modes and symlinks remain in
the archives. Each material's original URL and digest is in `manifest.json`.

| Material | Identity and use |
| --- | --- |
| glibc source | 2.28, commit `92d25389c255b0da9b56bc05694f0702cd22921a`, including startup and nonshared support source and `COPYING.LIB` |
| Hermetic LLVM Bazel module | 0.8.11, complete module source with glibc build definitions, helper rules, compiler defines, copied support source and notices |
| BCR module patch | Exact `module_dot_bazel_version.patch` applied to LLVM 0.8.11 by the Bazel Central Registry |
| Generated glibc headers | Exact x86_64 and AArch64 GNU 2.28 header archives selected by the module's header index |

The glibc patches are part of the supplied LLVM module. Apply them in order,
with one leading path component stripped:

1. `0001-Add-empty-config.h.patch` supplies the empty `include/config.h`.
2. `0002-Add-abi-tag.h.patch` supplies the Linux ABI tag header.
3. `0003-Adding-libc-modules.h.patch` supplies the module definitions header.

The module's `3rd_party/libc/glibc/glibc.BUILD.bazel` supplies the compilation
defines in place of a configure-generated `config.h`. It also selects copied
support source, including `csu/abi-note-2.31.S`. The entire module is supplied
so its transitive helper definitions, runtime rules and source notices remain
available. The original source archive alone would omit those inputs.

`manifest.json` is generated by
`crates/xtask/src/release_artifact/corresponding_source.rs`. It identifies the
candidate, original inputs, selected recipe files, ordered patches, and the
SHA-256 digest and mode of every outer archive member except itself. The
outer archive digest is bound by the signed native archive, avoiding a
self-referential manifest digest.

## Reconstruct and substitute glibc startup source

Use a native Linux x86_64 or AArch64 host with the maintained tools from the
application's `.bazelversion`, `rust-toolchain.toml` and setup documentation.
No toolchain or dependency version is changed by this procedure. Bazel can
retrieve other application dependencies and build tools using the supplied
locks; this is a source reconstruction route, not an offline vendor archive
of all dependencies or operating-system components.

The following example assumes the verified companion was extracted as
`/tmp/rustleaks-corresponding-source`. Start with a new
`/tmp/rustleaks-relink` directory. These commands extract the supplied
application and library materials and apply the actual release patches:

```sh
mkdir -p /tmp/rustleaks-relink/application
tar -xf /tmp/rustleaks-corresponding-source/application.tar -C /tmp/rustleaks-relink/application
tar -xzf /tmp/rustleaks-corresponding-source/inputs/92d25389c255b0da9b56bc05694f0702cd22921a.tar.gz -C /tmp/rustleaks-relink
tar -xzf /tmp/rustleaks-corresponding-source/inputs/hermetic-llvm-v0.8.11.tar.gz -C /tmp/rustleaks-relink
git -C /tmp/rustleaks-relink/hermetic-llvm-0.8.11 apply --no-index -p1 /tmp/rustleaks-corresponding-source/inputs/module_dot_bazel_version.patch
git -C /tmp/rustleaks-relink/glibc-92d25389c255b0da9b56bc05694f0702cd22921a apply --no-index -p1 /tmp/rustleaks-relink/hermetic-llvm-0.8.11/3rd_party/libc/glibc/0001-Add-empty-config.h.patch /tmp/rustleaks-relink/hermetic-llvm-0.8.11/3rd_party/libc/glibc/0002-Add-abi-tag.h.patch /tmp/rustleaks-relink/hermetic-llvm-0.8.11/3rd_party/libc/glibc/0003-Adding-libc-modules.h.patch
cp /tmp/rustleaks-relink/hermetic-llvm-0.8.11/3rd_party/libc/glibc/glibc.BUILD.bazel /tmp/rustleaks-relink/glibc-92d25389c255b0da9b56bc05694f0702cd22921a/BUILD.bazel
touch /tmp/rustleaks-relink/glibc-92d25389c255b0da9b56bc05694f0702cd22921a/REPO.bazel
```

For x86_64, edit
`/tmp/rustleaks-relink/glibc-92d25389c255b0da9b56bc05694f0702cd22921a/sysdeps/x86_64/start.S`.
An ABI-neutral demonstration inserts sixteen `nop` instruction lines directly
after `ENTRY (_start)`. The maintained proof uses this change. Keep the
copyright header and the remaining startup instructions.

Build and relink with both the supplied module and modified library source:

```sh
cd /tmp/rustleaks-relink/application
bazelisk --output_user_root=/tmp/rustleaks-relink/bazel build --config=release-linux-x86_64-gnu --distdir=/tmp/rustleaks-corresponding-source/inputs --override_repository=llvm+=/tmp/rustleaks-relink/hermetic-llvm-0.8.11 --override_repository=llvm++glibc+glibc_x86_64-linux-gnu.2.28=/tmp/rustleaks-relink/glibc-92d25389c255b0da9b56bc05694f0702cd22921a //crates/rustleaks-cli:rustleaks
/tmp/rustleaks-relink/application/bazel-bin/crates/rustleaks-cli/rustleaks --help
/tmp/rustleaks-relink/application/bazel-bin/crates/rustleaks-cli/rustleaks --version
```

For AArch64, edit `sysdeps/aarch64/start.S` directly after `_start:` and use
the native AArch64 build command:

```sh
cd /tmp/rustleaks-relink/application
bazelisk --output_user_root=/tmp/rustleaks-relink/bazel build --config=release-linux-aarch64-gnu --distdir=/tmp/rustleaks-corresponding-source/inputs --override_repository=llvm+=/tmp/rustleaks-relink/hermetic-llvm-0.8.11 --override_repository=llvm++glibc+glibc_aarch64-linux-gnu.2.28=/tmp/rustleaks-relink/glibc-92d25389c255b0da9b56bc05694f0702cd22921a //crates/rustleaks-cli:rustleaks
/tmp/rustleaks-relink/application/bazel-bin/crates/rustleaks-cli/rustleaks --help
/tmp/rustleaks-relink/application/bazel-bin/crates/rustleaks-cli/rustleaks --version
```

The repository overrides replace the actual startup and nonshared compilation
inputs while retaining the selected generated headers and linker recipes.
The application is rebuilt from source, so separate application object files
are not needed for this route. Other ABI-compatible changes can be made to
the supplied glibc or module-owned support sources using the same overrides.

## Maintainer generation and proof

`cargo xtask release-artifact fetch-source REPOSITORY_CACHE` explicitly
acquires the five fixed inputs and verifies their SHA-256 digests.
`prepare-source REPOSITORY_CACHE COMMIT OUTPUT` only reads those cached inputs
and exact Git candidate blobs. Preparation fails on missing or altered
inputs and has no network fallback. The archive is deterministic across the
two GNU native jobs and their isolated preparation directories.

`cargo xtask release-artifact relink-source ARCHIVE COMMIT TARGET WORK PROOF`
requires the matching native GNU Linux host and a new work directory. It
verifies the offered archive against the candidate before extracting it,
then performs the reconstruction above twice: first unchanged, then with
sixteen NOP instructions inserted at the glibc startup entry. It checks that
the modified executable's ELF entry contains the expected instruction bytes,
the original entry lacks that marker, and both native help/version smoke
checks succeed. Release preparation additionally requires the unchanged
reconstruction's binary SHA-256 to equal the selected native release binary.

The proof contains candidate, target, source archive digest, original and
modified startup digests, binary digests, instruction marker and smoke
results. It contains no local paths or timestamps. Publication retains the
actual native proof and its binding in the signed native archive; merely
constructing the source bundle does not establish that the proof passed.
